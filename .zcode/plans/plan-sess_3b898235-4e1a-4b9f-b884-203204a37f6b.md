# แผน: Database Client Component Suite + DataTable Grid Redesign

Branch ใหม่: `feature/db-client-components` (ตัดจาก `feature/code-editor-language-support`)

## สรุปสิ่งที่สำรวจแล้ว

- DataTable ปัจจุบัน (`src/compositions/data-table/`) มี sort/filter/pagination/selection ฝั่ง client ครบ แต่ยังไม่มี sticky header, density, ความกว้างคอลัมน์, เลขแถว, monospace numeric cell, column visibility และ controlled sort/page/filters (contract ฝั่ง server) — ตรงกับ roadmap ข้อ 4–8 ที่ค้างอยู่
- ไม่มี Tree component ในไลบรารี (จำเป็นสำหรับ schema browser)
- CodeEditor ที่เพิ่งสร้างมี `sql` language พร้อมใช้เป็นฐาน Query editor
- Virtualization เลื่อนไป phase ถัดไป (ใช้ pagination รองรับก่อน)

## Phase 1 — DataTable grid redesign (implement รอบนี้)

แก้ใน `src/compositions/data-table/` โดย**ไม่ทำลาย API เดิม** (prop ใหม่เป็น optional ทั้งหมด):

1. **Props ใหม่ (DataTable.types.ts)**
   - `density?: 'compact' | 'regular' | 'comfortable'` (default `regular`)
   - `stickyHeader?: boolean` + `maxHeight?: number | string` (จำเป็นคู่กันเพื่อ scroll แนวตั้ง)
   - `showRowNumbers?: boolean` — คอลัมน์เลขแถวฝั่งซ้าย
   - Controlled contract สำหรับ DB client: `sort?/onSortChange?`, `pageIndex?/onPageChange?`, `filters?/onFiltersChange?`, `totalRows?` (เมื่อให้ `totalRows` = โหมด server-side, component ไม่ filter/sort/paginate เอง)
2. **DataTableColumn เพิ่ม**: `width?: number | string`, `minWidth?: string`, `numeric?: boolean` (ชิดขวา + `--orizz-font-mono` + tabular-nums), `hidden?: boolean` ในระดับ initial
3. **CSS**: density ผ่าน CSS var (`--dt-cell-pad`), `thead th { position: sticky; top: 0 }`, sticky first column ด้วย `position: sticky; left: 0` (เฉพาะเมื่อเปิด), row-number cell แบบ muted mono
4. **Column visibility**: controlled `visibleColumnIds?/onVisibleColumnIdsChange?` + ปุ่ม settings ใน toolbar เปิด popover เลือกคอลัมน์ (ใช้ Popover primitive)
5. อัปเดต tests + stories (เพิ่ม story Density, StickyHeader, ServerMode, RowNumbers), CHANGELOG, roadmap (ปิดข้อ 4/5 บางส่วน)

## Phase 2 — Tree primitive (implement รอบนี้)

`src/components/tree/` — `TreeView` + `TreeItem`: props `items: TreeNode[]` (`id, label, icon?, children?, disabled?`), controlled `expandedIds?/onExpandedChange?`, `onNodeSelect`, `loadChildren?: (node) => Promise<TreeNode[]>` (lazy load), keyboard navigation (Arrow Up/Down/Left/Right) ตาม WAI-ARIA tree pattern, CSS module + tokens, tests + stories

## Phase 3–6 — Component ชุด database client (แผน ไว้ implement รอบถัดไป)

วางที่ `compositions/` (generic ไม่ผูก business domain ตามหลัก roadmap) แต่ละตัวแยก data layer จาก UI เหมือนแบบ CodeEditor:

- **`compositions/schema-tree/`** — SchemaTree บน TreeView: นิยาม `DbNode` (catalog/schema/table/view/column) ใน `schema.types.ts` (data layer), lazy load ผ่าน callback, icon ตามชนิด object
- **`compositions/query-editor/`** — QueryEditor ครอบ CodeEditor: ปุ่ม Run/Cancel, Ctrl+Enter, แยก statement ด้วย pure util `splitStatements()`, callback `onRun(sql)` + query history (`onHistoryChange`); UI ไม่รู้จัก backend
- **`compositions/results-grid/`** — ResultsGrid สร้างบน DataTable ใหม่: `ResultColumn` (name, dbType, nullable) → สร้าง column config อัตโนมัติ (numeric → `numeric: true`, null → "NULL" จาง, วันที่ → ISO), row numbers + density compact + sticky header เปิดเป็น default, ปุ่ม export ผ่าน callback `onExport(format)`
- **`compositions/connection-form/`** — ConnectionForm จาก Dialog + Form/Fieldset/TextField/Select: fields (name, engine, host, port, database, user, password, ssl) + callbacks `onTest`/`onConnect` (แอปเรียก backend เอง)
- **Playground**: `DatabaseClientShowcase.tsx` ประกอบร่างจริง — Sidebar + SchemaTree | Tabs(QueryEditor) + ResultsGrid + Toast "Query executed" ด้วย SplitPane

## Definition of done (ทุก component)

typed props, a11y (keyboard/aria), semantic tokens light/dark, loading/error/empty states, unit tests + Storybook stories, ผ่าน lint/typecheck/test/build, ไม่มี `any`/index key/static inline style
